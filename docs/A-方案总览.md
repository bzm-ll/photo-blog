# A. 方案总览

## 一句话

用 **Astro** 写好的静态网站，代码和照片都放在 **GitHub** 仓库里，**Netlify** 每次你改动就自动重新生成一次网站，**Decap CMS** 给你一个网页后台（像写公众号一样发作品），全部跑在免费额度内。

- 上线后你的网址长这样：`https://随便起的名字.netlify.app`
- 想换自己的域名（如 `yourname.com`）可以以后再加，域名本身约 70–100 元/年，这是唯一可能要花的钱，**不是必须**。
- 没有服务器要维护，没有数据库要备份，没有后台程序会挂掉。文章和照片就是你 GitHub 仓库里的文件。

## 技术栈与每个部件的作用

| 部件 | 作用 | 免费额度 | 难度 | 是否必须 |
| --- | --- | --- | --- | --- |

| **Tailwind CSS 4** | 排版与配色系统（已封装成设计规范） | 开源免费 | 你不用碰 | 必须 |

| **Netlify** | 自动构建 + 全球 CDN 托管 + 免费二级域名 + HTTPS | 免费版含 100 GB 流量/月、300 构建分钟/月（以官网为准） | ⭐⭐ 点几下 | 必须 |

## 为什么是这个组合（而不是别的）

- **为什么不用 WordPress**：要租服务器 + 装数据库，长期至少几十元/月，还要防漏洞、备份。不满足"全免费 + 不自建服务器"。
- **为什么不用 Notion / 语雀 做站点**：第三方渲染不可控，排版做不出杂志感，且随时可能改规则。
- **为什么不用 Hexo / Hugo**：也能做，但要自己拼主题；Astro 的组件化 + 图片自动优化（WebP/AVIF、响应式尺寸）是现成的，对你"大图 + 手机适配"的需求更省事。
- **为什么内容用 Markdown 存仓库**：没有数据库，迁移时就是复制文件夹；后台只是"往仓库里写文件的遥控器"，后台挂了内容还在。
- **为什么搜索用 Pagefind**：不需要 Algolia 那种付费服务，构建时把索引写进网站，零成本零运维，中文可用（不支持词干，但能匹配）。
- **为什么评论用 Giscus**：评论存在 GitHub Discussions（公开仓库免费），不需要数据库，也不用管垃圾评论的服务费。

## 三条后台路线（按省事程度排序）

1. **标准路线（本方案默认，已配好）**：Netlify Identity + Git Gateway。你在 `/admin/` 用邮箱密码登录，Decap 通过 Netlify 的函数代你提交到 GitHub。你**不用给别人开 GitHub 权限**。缺点：Netlify 官方把 Identity 归为"维护模式"（还能用、文档还在，但不再是主推产品），登录界面样式较旧。
2. **备选路线（Identity 万一不可用时）**：Decap 的 `backend: github` + 一个免费的 OAuth 代理（Netlify 官方提供 `netlify-cms-github-oauth-provider` 的开源部署方式）。多一步部署，稳定性取决于那份额外服务。做法写在 `docs/G-后台在线编辑.md` 末尾。
3. **零配置兜底**：直接去 GitHub 网页上编辑 `.md` 文件、拖拽上传图片，提交后 Netlify 自动发布。**永远不会失效**，只是没有可视化后台。

## 这个方案做不到的事（先讲清楚，免得白折腾）

- 会员/登录可见、付费下载 —— 静态站不做。
- 访客统计需要接第三方（如 Plausible/Umami，有免费额度但需另行注册），默认没接。
- 后台不支持"实时预览正式样式"（Decap 的预览是简化版）；发布后 1–2 分钟生效。
- 图片处理在构建时完成：一次传 200 张大图会让构建变慢（免费版每月 300 构建分钟，够用但不适合天天全量重传）。
- 表单收集（报名、投稿）没有后端；留言用 Giscus。
