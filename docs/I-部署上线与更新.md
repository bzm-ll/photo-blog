# I. 部署上线 + 后续更新

## 一、上线后你的三个网址

| 网址 | 是什么 | 谁需要 |
| --- | --- | --- |
| `https://你的名字.netlify.app` | 公开网站 | 所有人 |
| `https://你的名字.netlify.app/admin/` | 后台 | 只有你（要登录） |
| `https://app.netlify.com` | Netlify 控制台 | 只有你 |

## 二、每次发内容的完整流程（以后 90% 的时间都在这）

```
打开 /admin/ → 登录 → 选分类 → New → 填标题/传图/写正文
   → 点 Publish
   → 等 1–2 分钟（Netlify 自动构建）
   → 刷新网站，已上线
```

**改已有的内容**：后台里点那条内容 → 改 → Publish。
**下线一条内容**：要么在后台把 **存为草稿** 打开（推荐，可恢复），要么点条目右侧的 ⋯ → Delete（会从仓库删文件，但仍能在 GitHub 历史里找回）。
**删错了想找回**：GitHub 仓库 → **Commits** → 找到那次提交 → 打开文件 → **History** → 点旧版本 → 复制内容。

## 三、Netlify 控制台要看什么

### Deploys（部署记录）

每次提交都会触发一次构建，列表里显示 **Published**（绿）或 **Failed**（红）。

- 点进某次部署 → 有 **Deploy summary**（改了哪些文件）和 **Deploy log**（构建日志）
- 构建失败：拉到日志最底部，看最后 5–10 行，通常是
  - `cover is required` —— 忘了传封面图
  - `Invalid date` —— 日期写成了 `2025/05/12`，要写 `2025-05-12`
  - `Could not resolve "./xxx.jpg"` —— 图片路径不对

### 回滚（发错了想退回上一版）

**Deploys → 找到上一个绿色的部署 → 右上 ⋯ → Publish deploy**，30 秒内线上回到那一版。内容文件不会回滚，只回滚"网站快照"；要连内容一起退，就在后台改回去。

### Deploy Previews（先看再发）

如果你在后台用 Decap 的"草稿审核"模式（本项目默认没开），每次提交会生成一个临时预览网址，确认无误再合并。个人博客一般用不上，知道有这个就行。

## 四、更新代码（比如改了设计、加了页面）

1. GitHub 上打开要改的文件 → 右上铅笔 ✏️ → 改 → 底部 **Commit changes**
2. Netlify 自动检测到新提交 → 重新构建
3. 构建失败时线上仍是上一版（不会白屏），修好再提交

**本地改（推荐给改动大的时候）**：

```bash
npm install          # 第一次才需要
npm run dev          # 打开 http://localhost:4321 边改边看
npm run build        # 本地验证能否构建成功（必做）
git add -A && git commit -m "改了什么" && git push
```

## 五、换成自己的域名（可选，唯一可能要花钱的地方）

### 1. 买域名

| 渠道 | 价格区间（.com） | 说明 |
| --- | --- | --- |
| Cloudflare Registrar | 约 $10/年（成本价） | 续费不涨价，最推荐 |
| Namecheap / Porkbun | 约 $10–15/年 | 首年常有优惠 |
| 国内（阿里云/腾讯云） | 约 60–100 元/年 | 需要实名，**解析到国外 CDN 需备案**（不备案用不了国内 CDN，但我们用的是 Netlify，不走国内 CDN） |

> 用 `.netlify.app` 免费二级域名**完全够用**，SEO 也不歧视子域名。先跑起来，觉得值得再买。

### 2. 在 Netlify 绑定

1. **Site configuration → Domain management → Add a domain**
2. 填 `yourname.com` → **Verify** → **Add domain**
3. 按提示去域名商的 DNS 面板添加记录：
   - 主域名：加 **A 记录** 指向 Netlify 给的 IP（或改用 Netlify DNS，把 NS 改过去，更省事）
   - `www`：加 **CNAME** 指向 `你的名字.netlify.app`
4. 等 DNS 生效（几分钟到 24 小时）→ Netlify 自动签发 **HTTPS 证书**（Let's Encrypt，免费）
5. 在 **Domain management** 里设 **Primary domain**，另一条会自动 301 跳转

### 3. 换域名后必须改的 3 个地方

| 文件 | 改什么 |
| --- | --- |
| `astro.config.mjs` | `SITE_URL` |
| `src/lib/config.ts` | `url` |
| `public/admin/config.yml` | `site_url` + `display_url` |

**为什么必须改**：`sitemap`、`canonical`、分享卡片里的绝对地址都由这三处生成。不改的话搜索引擎会认为是两个重复站点。

## 六、免费额度什么时候会用完（以及用完了怎么办）

| 资源 | 免费版（以官网为准） | 你的实际用量 | 撞线了怎么办 |
| --- | --- | --- | --- |
| 带宽 | 100 GB/月 | 每访客平均 300–800 KB → 10 万访问/月 | 开 Cloudinary 分流，或压更小 |
| 构建分钟 | 300 分钟/月 | 每次 1–2 分钟 → 150–300 次/月 | 少改琐碎内容，攒一批一起发 |
| 站点数 | 不限 | 1 | — |
| Identity 用户 | 1,000 | 1 | — |
| GitHub 仓库 | 公开仓库无限制 | 1 | — |

> 个人摄影博客，正常更新频率（每周 1–3 篇），基本不可能撞线。

## 七、备份（重要，但很简单）

内容全在 GitHub 上，本身就有完整历史。额外做一次"离线备份"：

1. GitHub → 仓库页 → 绿色 **Code ▾ → Download ZIP**
2. 存到网盘/移动硬盘，每季度一次

照片原图（未压缩的 RAW）请另外存硬盘 —— **GitHub 不是相册**，长期存大量原图可能触碰仓库体积限制。

## 八、上线检查（第一次部署后立刻做）

- [ ] 手机 4G 打开首页，图片能出来、不是一片灰
- [ ] 点右上 **EN**，地址变成 `/en/`，内容变英文（缺英文的会显示中文）
- [ ] 点太阳/月亮图标，颜色切换且刷新后保持
- [ ] 点放大镜 → 输入"雾" → 有结果
- [ ] 打开任意作品详情页 → 图片能点开放大 → ESC 能关
- [ ] 底部页脚的联系方式不是 `[邮箱]` 占位符
- [ ] `/admin/` 能登录并成功发布一条测试内容
